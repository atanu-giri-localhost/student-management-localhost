## 3. Change & Final Production Review Policy

1. **All Decisions Remain Revisable Before Pilot:** Because these defaults are provisional, any business rule (`OD-01`..`OD-15`) can be adjusted before production launch; keep policy constants cleanly centralized in `src/config/` and `*.permissions.js`.
2. **Phase 2 External Credentials Gate (`OD-02`):** Phase 2 implementation will use `WHATSAPP_PROVIDER="MOCK"` for automated tests and local verification, alongside pluggable provider integration ready for the WhatsApp Business API credentials/template you supply next.
3. **Follow-Up Migrations Rule:** If any later policy revision requires new tables or columns (for example, `credit_notes` or partial reversals), author a new numbered SQL migration inside the owning domain track (`npx wrangler d1 migrations create sms-d1-<domain> <name>`) — never edit committed `migrations/<domain>/0001_init.sql`. Legacy single-D1 files are archived in `docs/archive/single-d1/`.
